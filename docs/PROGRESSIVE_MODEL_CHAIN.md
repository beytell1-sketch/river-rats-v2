# Progressive Model Chain — Design Plan

**Date:** 6 April 2026
**Status:** Approved
**Depends on:** Feature expansion 38→45 (shipped)

---

## Summary

Train specialist XGBoost models per opponent count via warm-start chain:

```
v8 HU (38-feat, existing)
  → warm-start on 200 3-way hands → v9-3way (45-feat, saved)
  → warm-start on 200 4-way hands → v9-4way (45-feat, saved)
  → warm-start on 100 5-way hands → v9-5way (45-feat, saved)
```

In production, `num_opponents` selects the model file. Each model is
permanent — later models never overwrite earlier ones.

---

## Why Progressive, Not All-At-Once

One model trained on 25k HU + 500 MW rows learns neither well. The MW
signal (0.8% of data) drowns in HU rows. Progressive works because
poker complexity scales incrementally with opponent count. 3-way is a
small step from HU. 4-way is a small step from 3-way.

XGBoost's `xgb_model` parameter in `.fit()` supports this natively:
load the existing model, continue training. New trees learn residuals
the base model gets wrong on the specialist data.

---

## Training Approach

For each step:
1. Copy the previous model file
2. Train further using `xgb_model=previous_model` (warm-start)
3. Training data = the specialist batch only (200 hands), NOT combined
4. Save as new file — previous model untouched
5. Evaluate on reference set, gate before proceeding

## Model Router

```python
# Pseudocode
MODELS = {
    1: GtoOracle("models/gto_model_v8_hu.json"),
    2: GtoOracle("models/gto_model_v9_3way.json"),
    3: GtoOracle("models/gto_model_v9_4way.json"),
}
# 4+ opponents → 5-way model (or highest available)
DEFAULT = GtoOracle("models/gto_model_v9_5way.json")

def predict(feat_dict, num_opponents):
    oracle = MODELS.get(num_opponents, DEFAULT)
    features = GtoOracle.features_from_dict(feat_dict)
    return oracle.predict(features)
```

Before a specialist exists, the router falls back to the nearest
available model.

## Labelling Protocol

~500 hands total, generated by self-play runner (infrastructure exists):

| Batch | Hands | Source | Labeller |
|-------|-------|--------|----------|
| 3-way | ~200 | Self-play 3-handed games | GTO Expert agent |
| 4-way | ~200 | Self-play 4-handed games | GTO Expert agent |
| 5-way | ~100 | Self-play 5-handed games | GTO Expert + solver on hardest 20% |

Each labelled decision has:
- All 45 features populated with real multiway values
- Expert GTO action label
- Opponent count at decision point (not hand start)
- Stratified by street, position, action type

## Gates

| Step | Gate Criteria |
|------|--------------|
| v9-3way | 3-way accuracy on 24 reference hands > v8; HU accuracy does not regress |
| v9-4way | 4-way accuracy on 12 reference hands > v9-3way on 4-way hands |
| v9-5way | 5-way accuracy on new 5-10 reference hands meets minimum threshold |

---

## Adjuster Evaluation

After each model trains, test with and without adjuster:
- Specialist alone beats specialist+adjuster → strip adjuster for that count
- Adjuster still helps → keep as safety net, examine which rules
- Expected: draw bypass and pot odds survive, bluff suppression becomes redundant
