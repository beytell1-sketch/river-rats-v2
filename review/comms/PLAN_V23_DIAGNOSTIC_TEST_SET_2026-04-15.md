# v2.3 Diagnostic Test Set — Design Document

---

## Section 1: Purpose

### What this test set is for

The diagnostic test set exists to answer one specific question: **has v2.3 reduced the bucket-first CHECK bias relative to v2.2?** That question cannot be answered cleanly on the existing MW-50 reference set because many of those hands were not selected to stress the bias being corrected. A purpose-built set allows targeted measurement.

The test set is a **pure diagnostic instrument**, not a ship gate. It will be run on both v2.2 and v2.3 after training completes, and the results will inform iteration decisions — not block release.

### Scope

- Total size: **30-50 hands**
- Format: same situation format as existing MW reference set (can be evaluated by the same reference_evaluator pipeline)
- Ground truth: owner-run GTO Wizard, one session, per the process in Section 4

### Anchor hands (stable comparators)

Two hands carry over from existing evaluation with their current labels unchanged:

| Hand ID | Label | Role |
|---------|-------|------|
| FB-40 | (existing) | Stability anchor — heads-up reference, confirms v2.3 did not regress on HU |
| MW-50 | (existing) | Stability anchor — existing multiway reference, confirms v2.3 did not regress on general MW accuracy |

Both v2.2 and v2.3 must match or exceed their current accuracy on FB-40 and MW-50 for the comparison to be valid. If a model regresses on these anchors, the diagnostic result is contaminated.

### What this test set does NOT cover

- v3.0 Action Distribution hands — separate backlog item, separate test set
- Track A training supplement design — that is the input side; this is the evaluation side
- Any heads-up or fold-decision patterns not connected to the BET/CHECK mixed-zone failure mode

## Section 2: Hand Patterns to Include

The 30-50 diagnostic hands are divided into four pattern groups. Each group targets a distinct failure mode observed in the v2.2 MW misses and the solver verification log.

### Pattern Group A: BET-CHECK mixed zones (10-15 hands)

**Definition:** Spots where the GTO Wizard solver assigns meaningful frequency to both BET and CHECK for the specific combo — neither action is below 20% in the solution.

**Why this group is central:** The solver verification log (d8886, d8963, BP4_21, d2788) shows that v2.2 systematically resolves mixed zones to CHECK. The model is not just wrong — it is directionally wrong in a consistent way. A test set that does not specifically sample from mixed zones will not expose this.

**Pattern requirements:**
- Solver BET frequency between 25% and 75% (both actions genuinely present)
- Flop or turn decision street (river mixed zones are mechanically different and lower priority)
- At least two different board textures represented (monotone / two-tone / rainbow)
- Hero position mix: at least 3 OOP, at least 3 IP, at least 4 sandwich (MIDDLE seat), which is where the bias is most pronounced per the MW miss profile
- Hand strength range: include both value-ish hands that have a checking option (top pair moderate kicker, overpairs on connected boards) and semi-bluffing draws that have a betting option

**Sourcing note:** These require solver queries to locate. The pool candidate approach (Section 3) is preferred over factory generation for this group because the mixed-zone property must be verified before inclusion — generating hands and hoping they fall in a mixed zone is inefficient.

### Pattern Group B: BP-pattern hands with full villain info (5-10 hands)

**Definition:** Spots from the BP (blind-versus-preflop-raiser) situation family, generated post-Track B fix, where both villain seats have complete position data.

**Why this group matters:** BP5_01 and BP4_21 in the solver verification log both showed CHECK bias. The current BP hands in training have incomplete villain data (the defect Track B fixes). Any BP hands in this diagnostic set must come from the fixed generator — they cannot be sourced from the existing BP pool.

**Pattern requirements:**
- Generated by `situation_factory.py` after Track B fix is committed and verified
- Both villain positions populated (`len(villain_positions) == num_opponents`)
- Hero is OOP (BB defending) — this is the BP-pattern configuration where the bias is documented
- Include at least 2 hands where the solver recommends BET at small sizing (25-33% pot), since BP4_21's key lesson was that solver bets small where the model checks
- SPR range 1.0-2.0 (the compression zone where BP decisions are most consequential per KB section 1.6)

**Sourcing note:** Cannot be sourced until Track B is complete. This group should be assembled in a second pass after the generator fix is verified.

### Pattern Group C: Passive-lean patterns from MW misses and d-series mixed spots (10-15 hands)

**Definition:** Hands that share structural features with the 10 documented MW misses — specifically the configuration where v2.2 predicts CHECK with high CALL probability mass, on a spot where the expert label (and likely the solver) says BET.

**The empirical signature from the MW miss HTML:**

All 10 MW misses share a near-identical feature cluster:
- `spr = 1.25` (every single miss)
- `villain_checked_back = 1` in 8 of 10 cases (checked around to hero)
- `hero_range_percentile = 0.00` in all 10 cases (feature not discriminating)
- Model assigns 30-65% probability mass to CALL despite CALL not being a legal action in these spots
- Model CHECK probability ranges 7-54%; BET probability ranges 2-22%

This is a coherent failure signature: the model is routing probability mass to CALL when the legal options are BET/CHECK, which depresses the BET output. The diagnostic set should include hands that recreate this structural configuration so we can measure whether v2.3 has corrected it.

**Pattern requirements:**
- SPR 1.0-1.5 (matching the miss cluster)
- Checked to hero with no prior bet on the decision street
- Hero holds a hand with genuine betting equity (top pair or better, or a strong draw meeting KB section 1.7 semi-bluff conditions)
- At least 5 of these hands should come from the MIDDLE position (sandwich) where position disadvantage interacts with the passive-lean bias
- Include both flop-decision and turn-decision hands (the MW misses are mostly turn; adding flop hands tests whether the fix generalises)

**Derivation from specific misses:**
The following 10 MW miss hands provide the template for this group. New hands should be structurally analogous (same position, similar hand strength category, similar board texture type) but not identical:

| Source miss | Key feature | Template for |
|-------------|-------------|--------------|
| d2410_CO_turn | MIDDLE seat, JK on flush-completing board, equity 0.43 | MIDDLE seat, moderate equity, flush board |
| d2920_BB_turn | OOP, two-pair equivalent, equity 0.50, villain aggression present | OOP, strong made hand, one villain aggressor |
| d3178_CO_river | MIDDLE seat, AA underpair on KQJ board, equity 0.62 | MIDDLE seat, overpair on high-card board |
| d1983_HJ_turn | MIDDLE seat, AJ top pair, equity 0.43, both villains passive | MIDDLE seat, TPTK, both villains checked back |
| d1562_HJ_turn | MIDDLE seat, 77 underpair with low equity 0.38 | MIDDLE seat, low equity BET candidate |
| d8411_BB_turn | OOP, A8 middle pair, flush draw completing, equity 0.67 | OOP, strong hand on threatening board |
| d8886_BB_flop | OOP, QJ top pair, first-action flop, equity 0.62 | OOP, flop first-decision spot |
| d1454_CO_turn | MIDDLE seat, TJ top pair + flush draw, equity 0.44 | MIDDLE seat, combo draw |
| d3688_BB_flop | OOP, K8 top pair on KT4 — this is a CHECK miss (model BET'd) | OOP, passive-lean reversal — see Group D |
| d3229_BTN_river | IP, QJ rivered pair, equity 0.60 | IP river value BET |

Note that d3688 is structurally reversed (model over-bet, expert CHECK) — it belongs in Group D below, not this group.

### Pattern Group D: Calibration reversals (5 hands)

**Definition:** Spots where the naive read (and where v2.2 makes its mistake) is the opposite of the GTO action. Analogous to MW-30, MW-33, MW-50 in the existing reference set — the "tricky" hands that expose whether a model truly understands 3-way dynamics or is applying a surface heuristic.

**Why this group matters:** Reversals test the hardest failure mode: not just passivity bias, but genuine misread of the situation. They prevent a model that simply "bets more" from gaming the diagnostic — a model that correctly identifies when NOT to bet (the reversal cases) demonstrates real calibration improvement.

**Pattern requirements:**
- 2-3 hands where the naive read is BET (strong hand, good equity) but GTO says CHECK — traps, pot-control spots, hands that benefit from letting opponents catch up
- 2-3 hands where the naive read is CHECK (medium hand, uncertain) but GTO says BET — protection bets, thin value, or spots where checking gives up too much equity against two opponents
- d3688_BB_flop (from the MW miss HTML) is a natural candidate for this group: BB holds K8 top pair on KT4 flush board, model bet, expert CHECK — the flush draw and second villain create a pot-control argument the model missed
- Board textures should include at least one paired board and one monotone board, as these are where reversal intuition most commonly misleads

## Section 3: Sourcing Strategy

### Summary table

| Group | Count | Primary source | Secondary source | Blocker |
|-------|-------|---------------|-----------------|---------|
| A: BET-CHECK mixed zones | 10-15 | Existing training pool + solver screening | Factory generation with solver verification | None — can start now |
| B: BP-pattern with full villain info | 5-10 | Factory generation (post-Track B fix) | None | Track B must complete first |
| C: Passive-lean MW patterns | 10-15 | Existing training pool (structurally analogous) | Factory generation | None — can start now |
| D: Calibration reversals | 5 | d3688 from MW miss HTML + existing pool | Manual construction | None — can start now |

### Sourcing detail by group

**Group A — mixed zones:**
The most efficient approach is to start from the existing training pool (`training-data/v2_2_training.csv`) and filter for hands where the Pass 1 team was split BET/CHECK (2-2 or 3-1). These are natural candidates for solver-verified mixed zones. The d-series verification log already identified four such hands (d8886, d8963, d4312, BP4_21); a full pool scan will surface more. Target: 20-30 candidate hands, then owner solver-screens to confirm which fall in the 25-75% frequency band. Expect a 50-60% hit rate — some Pass 1 splits will resolve to pure solver actions.

**Group B — BP post-fix:**
These cannot be sourced from the existing pool because the existing BP hands have the villain data defect. The Track B fix must be verified first (including the re-generation of existing 185 BP situations to confirm villain lists are complete). After that, a factory run of 20-30 BP situations provides the candidate pool; owner solver-screens for the SPR 1.0-2.0 range and selects 5-10 for inclusion.

**Group C — passive-lean patterns:**
The MW miss HTML provides 9 structural templates (excluding d3688 which goes to Group D). The sourcing preference is to find structurally analogous hands already in the existing pool rather than generate new ones — this avoids inflating the diagnostic set with factory-generated hands that may carry other artefacts. If the pool yields fewer than 8 matches per template, factory generation fills the gap.

**Group D — calibration reversals:**
d3688 is a confirmed candidate (already solver-verified: expert CHECK, model BET). The remaining 4 reversals should be drawn from the existing pool by searching for MW-50-analogous spots: hands where the expert label is the less-obvious action. If the pool is thin on reversals, the owner can nominate 2-3 from their own GTO Wizard session history — these are spots the owner already has intuition about.

### Inclusion criteria

A hand is eligible for the diagnostic set if it meets ALL of:
1. Three-way postflop decision (no heads-up or 4-way hands)
2. Decision is BET or CHECK (no raise/fold/call decisions)
3. Hero is not first in with no prior action unless that is the specific pattern being tested (Groups A and C)
4. Board texture is known (all 3+ cards visible for flop/turn/river decisions)
5. SPR at decision point is documentable from the hand record
6. Villain action history on prior streets is complete and unambiguous

### Expected difficulty distribution

| Difficulty | Definition | Target count |
|------------|-----------|--------------|
| Easy | Solver says pure/majority action (>70%), model should agree | 5-8 |
| Standard | Solver leans one way (55-70%), reasonable hand to get right | 10-15 |
| Hard | Genuine mixed zone (35-65%), solver mixes meaningfully | 10-15 |
| Contested | Calibration reversal, counter-intuitive GTO action | 5 |

The test set is intentionally harder than the existing MW-50 reference set. Easy hands are included only to confirm the model has not regressed on unambiguous spots.

## Section 4: Ground-Truth Process

### Who runs it

Owner only. No agent runs GTO Wizard. This is consistent with the project protocol that solver output is verified by the owner, not generated by the pipeline.

### Pre-flight checklist (per feedback_solver_preflight.md)

Before running any hand in GTO Wizard, verify:

1. **Sequence validation:** Confirm the action sequence is internally consistent (preflop action is consistent with positions, prior streets are consistent with SPR at decision point).
2. **Bet size alignment:** Any prior bets in the hand history must match GTO Wizard solver options exactly. Flop: 25% or 66% pot. Turn: 33% or 75% pot. River: 33%, 75%, or 150% pot. If a hand's prior action used a non-standard size, the hand is excluded from the set.
3. **Position verification:** Confirm hero seat (OOP/MIDDLE/IP) maps correctly to the GTO Wizard tree structure.
4. **Stack depth:** Confirm SPR at the decision point matches the effective stack in GTO Wizard.

Any hand that fails pre-flight is dropped. Do not adjust the hand to fit the solver — if the hand was generated with a non-standard prior bet size, it belongs to the generator defect category and should be flagged back to Track B.

### What to record per hand

For each hand that passes pre-flight:

| Field | What to capture |
|-------|----------------|
| Primary action | The highest-frequency action (BET or CHECK) |
| Primary frequency | Percentage of combos the solver plays that action |
| Mixed actions present | Yes/No — if Yes, record secondary action and its frequency |
| Sizing (if BET) | Which sizing the solver uses (25%/33%/66%/75%) |
| Verdict | A: solver majority BET, B: genuine mix, C: solver majority CHECK |
| Notes | Any combo-level nuance (suit effects as in d8886/d8963) |

### Session structure

The owner should run this in a single dedicated session rather than spreading it across multiple days. The diagnostic set is designed to be internally coherent — doing it in one session reduces the risk of inconsistent solver tree configurations between hands.

Estimated time: 2-3 hours for 30-50 hands, assuming pre-flight is fast on well-formed hands. Group B (BP post-fix) requires a separate session after Track B completes.

### Labelling convention

Following the project's solver verification conventions (from the verification log):

- Verdict A (solver majority BET, 55%+): label = BET
- Verdict B (genuine mix, 35-65%): label = BET if the specific combo bets, CHECK if it checks, with flag "mixed"
- Verdict C (solver majority CHECK, 55%+): label = CHECK

This is consistent with how d8886 and d8963 were handled in the verification log (combo-specific label applied, flagged as boundary).

## Section 5: Success Criteria

### Primary measurement

The diagnostic test set produces an **accuracy score on the mixed-zone subset** (Groups A and B) for both v2.2 and v2.3. Success is defined as BOTH of the following:

> 1. v2.3 accuracy on Groups A+B is at least 5 percentage points higher than v2.2 accuracy on the same hands, AND
> 2. **(Track 6 §2.4 amendment)** v2.3 absolute accuracy on Groups A+B is at least **70%** in absolute terms — not merely an improvement over a weak v2.2 baseline.

The 70% absolute floor prevents the case where v2.2 scores 40% on the mixed-zone subset and v2.3 scores 46% — a 6pp improvement that nominally passes the first criterion but leaves the model failing the majority of mixed-zone hands. Both criteria must hold for the diagnostic to count as a successful bias correction.

This is a direct measurement of the defensive multiway-checked-through CHECK bias correction. A 5pp improvement on a 25-35 hand subset (Groups A+B) means roughly 1-2 additional correct predictions — achievable if the bias correction is genuine, non-trivial if it is not. The 70% absolute floor ensures the correction lands at a usable accuracy level.

### Stability requirement

The comparison is valid only if:

- v2.3 accuracy on FB-40 is >= v2.2 accuracy on FB-40
- v2.3 accuracy on MW-50 is >= v2.2 accuracy on MW-50

If v2.3 improves on the diagnostic set by trading regression on the anchors, the result is not a success — it means the training changes over-fit to the bias-correction pattern.

### Secondary measurements (diagnostic, not pass/fail)

| Measurement | What it tells us |
|-------------|-----------------|
| v2.3 CHECK frequency on Group C hands | Is the passive-lean pattern reduced in frequency? |
| v2.3 CALL probability mass on BET/CHECK-only spots | Has the illegal-action probability leak been reduced? |
| v2.3 accuracy on Group D reversals vs v2.2 | Has calibration improved on tricky spots, or just overall aggression increased? |
| Difficulty-stratified accuracy | Does v2.3 improve on Hard hands specifically, or does it improve across the board? |

The Group D reversal accuracy is particularly important as a sanity check. A model that simply learned "bet more in MW" will score worse on reversals. A model that genuinely improved its mixed-zone reasoning will maintain or improve on reversals.

### Group D Regression Fallback (Track 6 §2.4 amendment)

**If v2.3 regresses on Group D reversal accuracy by more than 1 hand vs v2.2, stop and investigate before ship.**

Group D contains 5 reversal hands. A regression of >1 hand (i.e. v2.3 gets ≥2 fewer Group D reversals correct than v2.2) indicates the training supplement shifted the model toward a naive "bet more" response that degrades calibration on the hardest spots. That is exactly the failure mode the reversal group exists to catch.

When this fallback fires:
1. Halt ship/promote decisions on v2.3.
2. Investigate whether supplement over-represents aggressive actions beyond what the precondition predicate warrants (Track 6 §2.2 bucket).
3. Consider whether class weight relaxation (v2.3 scope Section 1 note) was too aggressive.
4. Re-scope before any further iteration.

This fallback is enforcement-level — not a diagnostic note. A v2.3 model with Group D regression > 1 hand does not ship regardless of how favourable its Groups A+B numbers look.

### What this test set does not decide

- Ship / iterate decision for v2.3 — that is a separate gate with its own criteria
- Whether v2.3 training changes were the right approach — the scope document (Track A) defines those
- Performance on heads-up or 4-way decisions

### Format of results

When the comparison is run, results should be reported as a table:

| Subset | v2.2 accuracy | v2.3 accuracy | Delta | Pass? |
|--------|-------------|-------------|-------|-------|
| FB-40 anchor | — | — | — | >= 0 |
| MW-50 anchor | — | — | — | >= 0 |
| Groups A+B (mixed zones, ~25-35 hands) | — | — | — | >= +5pp AND v2.3 >= 70% absolute |
| Group C (passive-lean, ~10-15 hands) | — | — | — | diagnostic |
| Group D (reversals, 5 hands) | — | — | — | regression > 1 hand = STOP (Track 6 §2.4) |
| Full diagnostic set (30-50 hands) | — | — | — | diagnostic |

The delta on Groups A+B is the single headline number. Everything else is context.
