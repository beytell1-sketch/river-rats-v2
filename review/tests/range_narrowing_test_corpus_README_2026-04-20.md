# Range-Narrowing Test Corpus — Companion README

## What this is

A structured YAML corpus of **81 synthetic hand scenarios** exercising
the v2.4 Stage 3.5 `narrow_by_action_history` fix in
`river-rats-core/range_narrowing.py`. Feeds:

1. Unit tests (direct call into `narrow_by_action_history`)
2. Integration tests (through `classify_villain_range` in `feature_extractor.py`)
3. Retroactive audits (compare pre-fix vs post-fix feature columns on
   v2.3.1 training rows)

## Structure of a case

Every entry carries:

- `id`: stable identifier (e.g., `T_A03_bet_check_bet_chain`)
- `category`: A-K bucket (see coverage matrix below)
- `description`: one-line shape summary
- `hero_position`, `villain_position`, `opener`: positional context
- `hero_cards` (optional): anchor / owner cases specify
- `board`: full runout (3-5 cards depending on `decision_street`)
- `action_history`: ordered list of `{street, position, action}` dicts
  (or 3-tuples — see `T_K17`)
- `decision_street`: `flop` / `turn` / `river` / `preflop` — the street
  whose decision the composition targets
- `expected_composition_pre_fix` / `expected_composition_post_fix`:
  four-bucket villain composition (`villain_tp_pct`,
  `villain_medium_made_pct`, `villain_draw_pct`, `villain_air_pct`)
  approximated from the frequency tables in `range_narrowing.py`
- `expected_action` (optional): only on calibration anchors
- `tolerance` (optional): `strict` for anchors
- `notes`: human explanation + `[approx]` marker + references to spec
  sections or review flags

## How expected values were derived

**Not from running the reference implementation.** Generated by hand
from:

1. Solver-grounded `FLOP/TURN/RIVER_BETTING_FREQUENCIES` + `CHECKING_FREQUENCIES`
   (rows 75-146 of `range_narrowing.py`)
2. Heuristic `FLOP/TURN/RIVER_CALL_FREQUENCIES` (rows 165-194)
3. Assumed generic preflop baseline composition:
   - TP+ (nuts + strong_value + good_value): ~0.30
   - medium_made: ~0.15
   - draw: ~0.15
   - air (+ bluffs + weak_made): ~0.40

For flop/turn/river baseline tightenings by position (UTG vs BTN vs
BB-defend) we shifted the TP+ component ±5-15 pp and compensated in air.
Call-through + check-through chains follow the mechanical rule

```
new_weight[cat] ∝ old_weight[cat] × freq[cat]
```

normalized across categories. Values rounded to 2 dp. **Refine against
the reference implementation before using as strict regression oracles
— treat as shape-tests initially.**

## Known limitations of the corpus

1. **Approximate expected values.** Call them shape-tests until the
   reference impl produces canonical numbers. Once those exist, rewrite
   `expected_composition_post_fix` from the reference run and use these
   as strict oracles. Pre-fix column should match v2.3.1 extraction
   output for retroactive-audit purposes.

2. **Single baseline assumption.** The corpus assumes one generic
   preflop composition (TP+ 0.30 / med 0.15 / draw 0.15 / air 0.40).
   Real baselines vary with position — `T_G01` (UTG-tighter), `T_K02`
   (3bet-pot tighter), `T_K12` (UTG-tight) reflect this, but fine-grained
   tuning of per-position baselines is out of scope for corpus v1.

3. **Raise-aware call-narrow is NOT tested.** The Stage 3.5 spec ships
   generic CALL narrowing; `T_C02` and `T_K15` document the limitation
   but don't assert a different expected value from generic-call cases.

4. **Multiway cross-conditioning is NOT tested.** Category E tracks
   primary-villain only, consistent with v2.4 scope. v2.5 backlog
   (TICKET_V25_PRO_LEVEL_NARROWING_GAPS).

5. **Board-texture expected values lean on `classify_hand` correctness.**
   If the hand classifier mis-buckets an edge case (e.g., paired-board
   full-house on river), the chain output drifts. Board-texture cases
   (F01-F10) surface these drifts.

## Usage patterns

### Unit tests

```python
import yaml
corpus = yaml.safe_load(open('review/tests/range_narrowing_test_corpus_2026-04-20.yaml'))

for case in corpus:
    if case['expected_composition_post_fix']['villain_tp_pct'] is None:
        # Terminal / degenerate / safety-rail — test error path
        continue
    v_range = get_villain_range(...)
    narrowed, meta = narrow_by_action_history(
        v_range, case['board'], case['action_history'],
        case['villain_position'], case['decision_street']
    )
    actual = classify_composition(narrowed)
    assert_close(actual, case['expected_composition_post_fix'], tol=0.05)
```

### Retroactive audit

For every v2.3.1 training row that matches a corpus shape, re-extract
villain-composition columns with the new chain. Compare to stored
values. Document the distribution shift per spec §5 step 6.

### Calibration-anchor regression

Load cases with `tolerance: strict` (category H). For each, feed
through the full oracle and check that `expected_action` is top-1. d2410
is the critical one — flop-only anchors are ZERO-impact controls.

## Notes per category

### A. Simple chains (T_A01 + T_A01b-T_A10)
- `T_A01` (`T_A01_invalid_schema_sentinel`) uses an invalid action
  token `CHECK_RAISE` and must be silently skipped by `_action_to_narrow`
  (maps unknowns to `skip`). All composition expected values are `null`
  — this is a don't-crash test, not a correctness oracle. The correct
  triple-barrel shape is in `T_A01b`.
- `T_A07` (check-check-bet) is the **owner's exact scenario shape**.
  Expect medium collapse + more air than pre-fix.

### B. Double-action (T_B01-T_B05)
- `T_B02` is INVALID BY CONSTRUCTION — villain cannot bet + raise own
  bet on same street. Chain should log and not crash. Treat as a data-
  hygiene test, not a correctness oracle.
- `T_B03` tests the baseline-range **opener** field is updated to BB
  after a BB-3bet line.

### C. CALL edge cases (T_C01-T_C08)
- `T_C03` and `T_C04` intentionally have identical expected outputs.
  v2.4 CALL narrow is sizing-agnostic (known limit).
- `T_C08` tests FOLD-terminal handling mid-chain.

### D. Street-transition (T_D01-T_D06)
- `T_D03` is THE owner scenario with flop-BET + turn-CHECK + river-BET
  — the linchpin case for the fix.
- `T_D05` reproduces d2410's shape (without cards).

### E. Multiway (T_E01-T_E05)
- `T_E02` explicitly tests that a non-primary FOLD doesn't break the
  chain.
- `T_E05` tests chain-through-multiway (primary tracks across
  non-primary folds).

### F. Board-texture (T_F01-T_F10)
- Covers 10 distinct texture classes applied to the same action line
  (bet-call-check turn) so texture effects can be isolated.

### G. Position (T_G01-T_G05)
- Tests the baseline-range picker: UTG opens tight; BB defends wide;
  3bet-pot baselines tighter still.

### H. Anchor regression (T_H01-T_H05)
- **T_H01** (d2410): ONLY anchor expected to shift. Action must
  remain BET after fix for gate to pass.
- T_H02-T_H05: flop-only LITMUS anchors. Per spec, flop decisions do
  NOT chain prior-street actions → pre==post EXACTLY. If any of these
  shift, the chain has leaked into flop decisions → STOP.

### I. Empty/degenerate (T_I01-T_I03)
- `T_I01` tests the fallback path per spec §3.2 (empty history →
  facing_bet single-street narrow, preserving pre-fix behavior).
- `T_I03` tests the FOLD-terminal return-empty path.

### J. Owner's scenarios (T_J01-T_J03)
- `T_J01` board is reconstructed generically because the playtest
  features log was empty.
- `T_J02` exercises all four narrow classes (BET / CHECK / CALL / BET)
  in one line.
- `T_J03` is a blocker-feature test — downstream `flush_block_pct` is
  expected to rise post-fix.

### K. Extra shape coverage (T_K01-T_K20)
- Adds breadth for CI variance; shapes overlap with A-J but with
  different board/positions. T_K16 + T_K18 are specifically safety-rail
  tests (weight-floor, schema-mismatch).

## Open questions flagged to implementers

1. **Baseline composition picker.** The corpus assumes a generic
   baseline (0.30/0.15/0.15/0.40). `get_villain_range` must return
   position-aware ranges; the test harness may need a per-position
   baseline fixture if the reference impl's output differs materially.
2. **Draw reclassification on river.** `narrow_to_betting_range` and
   `narrow_to_checking_range` reclassify `draw → air` on river per
   rows 478-480 / 541-543. Corpus expected values assume the same in
   `narrow_to_continuing_range` (rows 621-624). Verify.
3. **Preflop-only decision (T_K09).** Whether `classify_villain_range`
   is even called on preflop decisions is a design question. Left
   `null` in expected values.
4. **Anchor exact compositions.** T_H anchors use the generic
   baseline — actual v2.3.1 compositions on these hands will differ.
   Refine from real v2.3.1 feature columns before strict-asserting.
